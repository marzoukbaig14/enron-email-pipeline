## Mailbox selection candidates

Three candidate sets, each >=5 mailboxes and >=10,000 emails. **I am not choosing** - this is for the D-010 decision.

**A. Largest volume** (125,381 emails): kaminski-v, dasovich-j, kean-s, mann-k, jones-t
- Tradeoff: most data and most duplicates to find, but slowest to ingest and dominated by a few huge mailboxes.

**B. Most edge cases**
- by count (109,948 emails): dasovich-j, kean-s, jones-t, mann-k, farmer-d
- by rate, files>=1,000 (10,278 emails): solberg-g, meyers-a, linder-e, whalley-g, blair-l
- edge_score = folding + date fails + defects + multipart + non-ASCII + attachment refs + missing headers.
- Tradeoff: best stress test for the parser; the by-rate set is less dominated by sheer size but mixes in smaller mailboxes.

**C. Most cross-folder duplication**
- by count (125,381 emails): dasovich-j, kaminski-v, kean-s, mann-k, jones-t
- by rate, files>=1,000 (24,079 emails): linder-e, guzman-m, symes-k, merriss-s, rodrique-r
- dup_files = files whose exact body appears in >1 file anywhere; in this corpus every such group is cross-folder (same-folder = 0).
- Tradeoff: best exercise for dedup logic; the by-count set overlaps A since big mailboxes naturally hold more dups.

## Surprises (things that would break a naive parser or dedup)

- Folded To/Cc headers (89,586+ files): recipients span multiple lines; splitting on the first line loses addresses.
- 132,236 byte-identical bodies appear across different folders - the Enron habit of filing one mail in several folders. Exact-body dedup must key on more than body, or it will merge legitimately-distinct filings.
- X-Folder rarely matches the real folder name, so it cannot be used as ground truth for folder.
- To fields reach 1,029 recipients - watch for huge normalized recipient tables and distribution-list blasts.
- Empty-body files were excluded from exact-dup detection on purpose (they would otherwise form one giant false group).
